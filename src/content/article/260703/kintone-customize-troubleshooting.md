こんにちは、だいちゃんです。

kintone のサポートするお仕事をしていたり、カスタマイズやプラグインを [作って売ったり](https://udcxx.stores.jp/) させていただいている僕が、「kintone をカスタマイズしたはずなのに動かない！」とか、「前任者が作ったカスタマイズが思ったように動作しない」みたいな場合によく提案するトラブルシューティング方法をまとめてみました。

## 1. 読み込まれているか確認しよう

まず大前提として、該当のアプリにカスタマイズが読み込まれているかを確認しましょう。

カスタマイズが開くはずだと思われるページで F12 キーを押すか、何もないところで右クリック > 検証 をクリックして、ブラウザの開発者ツールを開きます。

**Sources** タブを開き、 xxx.cybozu.com > k > api/js の順に展開していきます。

![](/images/260704_1.jpg)

`download.do?app={アプリID}` になっているものがアプリに適用されていて、実際に読み込まれている JavaScript や CSS にあたります。さらに、その後ろに書かれている `jsType` が DESKTOP になっているものは PC 用の JavaScript で、 `jsType` が DESKTOP_CSS になっているものは PC 用の CSS です。

読み込まれているはずのカスタマイズ数と一致しない場合、読み込みがうまくいってない可能性があります。

読み込まれていな場合、以下のヘルプページを参考に再設定してみましょう。

* [JavaScriptやCSSでアプリをカスタマイズする | kintone ヘルプ](https://jp.kintone.help/k/ja/app/customize/js_customize)

設定時のよくあるミスとしては、

* 「適用範囲」が「アプリ管理者だけに適用」や「適用しない」になっている
* スマートフォン用の画面で使いたいのに、PC用のカスタマイズしか適用されていない
* 設定後、アプリの更新を行っていない

などもあるので、注意して見てください。

ちなみに、kintone には **全体カスタマイズ** と **アプリカスタマイズ** の 2 つがあるのですが、 `download.do` の後ろに `app=` と付かないものは全体カスタマイズの JavaScript や CSS になります。全体カスタマイズが読み込まれない場合は、 `app=` が無いものを探してみてください。


## 2. エラーが出ていないか見てみよう

正しく読み込まれているのに、想定した動きをしていない場合、コンソール画面にエラーが出ていないか確認してみましょう。

先ほどと同様に、カスタマイズが開くはずだと思われるページで F12 キーを押すか、何もないところで右クリック > 検証 をクリックして、ブラウザの開発者ツールを開きます。

次に **Console** タブを開きます。

下記のように何も表示されていないのが正常な状態です。

![](/images/260704_2.jpg)

赤文字でエラーが出ていたら、カスタマイズがうまく動いていないかもしれません。次章を参考にデバッグしてみましょう。


## 3. デバッグしてみよう

ちょっとハードルが高くなりますが、実際に読み込まれている JavaScript や CSS のソースコードを元に、正しく動かない箇所を特定し、修正して行きます。ここでは特に JavaScript について方法を見ていきます。

ちなみに、ここで紹介する方法以外にも cybozu developer network にはデバッグに関する記事がいくつか掲載されているので、参考にしてみてください。コミュニティで相談するのもありかも。

* [動かない？そんな時はデバッグをしてみよう！入門編 - cybozu developer network](https://cybozu.dev/ja/kintone/tips/development/development-productivity/debug/debug-introduction/)
* [デバッグをしてみよう - cybozu developer network](https://cybozu.dev/ja/tutorials/hello-kinapi/debug/)

### 3-1. ブレークポイントを打つ

再びブラウザの開発者ツールを開き、 **Sources** をクリックします。

デバッグしたい JavaScript ファイルを選択すると、右側にソースコードが表示されます。デバッグしたい行の行番号を右クリック > Add breakpoint でブレークポイントを設定し、ページをリロードすると、ブレークポイントを設定した箇所で処理が一時停止し。データが取れてるか？条件分岐の条件に正しい値が渡ってるか？などが確認できます。

特に、 if 文の条件分岐の箇所などに仕込むとミスが見つけやすかったりします。

### 3-2. console.log を仕込む

ソースコードを直接編集することになりますが、 console.log でログを仕込むのも有用です。

ソースコードをエディタで開き、デバッグしたい部分に console.log(’表示したい文字’) または console.log({表示したい変数}) を入れて保存し、アプリに適用させます。

* 例：変数 hoge の内容を確認したい場合 → console.log(hoge)

ブラウザの開発者ツール > Console に指定した文字列が表示されるので内容を確認し、意図した値になってるかを確認します。

### 3-3. AI に聞いてみる

最近の AI は普通に賢いので、適格なプロンプトで投げれば数回の修正で意図した動作になることが多いです。

ChatGPT などに JavaScript ファイルを添付して、想定する動作・実際に発生する現象（可能なら画面キャプチャーも）を添付して相談すると、解決策や、修正済みのコードを提示してくれます。

次のような文言も付け加えると、より正確に kintone API で利用可能な範囲内で回答してくれる確率が上がる気がします。

> kintone API ドキュメント（ https://cybozu.dev/ja/kintone/docs/ ）も参考にしてください 

ちなみに、アプリに適用されているソースコードは、アプリの設定 > JavaScript / CSS でカスタマイズから、ファイル名をクリックすることでダウンロードできます。

## 4. それでも解決しないとき
